### 质疑点成立的部分
- 之前批量探测用的 prompt 固定为「只回复两个字：正常」；chatgpt2api 有
  chat_completion_cache（cache_key = model + messages 哈希），同 model+同 prompt
  的后续账号请求会命中缓存。因此 id=73 的 6 个模型是真实上游调用，id=74~77 的
  结果可能是缓存命中——结论方向对，但证据强度不够，已复核。

### 复核方法（绕过缓存）
- 新注册 id=78/79 两个 free 号，每个请求 prompt 里注入**唯一随机 token**
  （uuid，每请求不同）→ cache_key 必然不同 → 全部走真实上游。
- 同时做 stream=true SSE 冒烟 + /api/logs 调用记录核对。

### 复核结果（两个账号全部通过）

## 2026-08-07 追加：模型真实身份 + 思考档位验证（直连上游 SSE）

### 问题
用户反馈：chatgpt2api 里「超高思考的 gpt-5.6-sol」回答错误，怀疑 sol/titan/luna
是同一模型或思考没生效；并提到最新 codex 思考档位有新增区分。

### 方法
在容器内直连上游（绕过 chatgpt2api 公有 API 剥离 metadata 的层），
用注册机新号 AT + 代理 POST /backend-api/conversation，
解析 SSE 的 message.metadata.model_slug / default_model_slug / thinking_effort /
reasoning_status / reasoning_start_time / reasoning_end_time / cot_version。

### 证据（id=85 / id=87 两个新 free 号）
| 请求 model | 请求 thinking_effort | 上游 model_slug | default_model_slug | 结果 |
|---|---|---|---|---|
| gpt-5.6-sol | （无） | gpt-5-5（id=85）/ gpt-5-6（id=87） | gpt-5.6-sol | 称球题答对 3 次 |
| gpt-5.6-sol | extended | gpt-5-5（id=85） | gpt-5.6-sol | 答对 3 次 |
| gpt-5.6-luna | extended | gpt-5-5（id=85） | - | 答对 3 次 |
| gpt-5.6-titan | extended / (无) | gpt-5.6-titan（独立） | - | 答对 3 次 |
| gpt-5.6-sol | ultra（绕过 normalize 直传） | gpt-5-6 | gpt-5.6-sol | 200 OK，metadata 回显 thinking_effort=ultra，答对 |

关键结论：
1. **sol/luna 不是独立模型**：上游实际执行的是 gpt-5-5 或 gpt-5-6（按账号可用性回落），
   default_model_slug 才是 gpt-5.6-sol。titan 是独立 slug gpt-5.6-titan。
   → 用户「感觉不像是 sol」正确：它本来就不是独立权重，行为=gpt-5-5/5-6。
2. **思考真实发生**：metadata 有 reasoning_status=reasoning_ended、
   reasoning_start_time/end_time（0.4s 级）、cot_version=v5；
   但 reasoning_recap_type=**hide_all** → SSE 不返回 thinking 内容 parts，
   chatgpt2api 侧永远看不到思考过程（不是假思考，是协议隐藏）。
3. **上游接受 thinking_effort=ultra**（HTTP 200 + metadata 回显），拒绝 minimal（HTTP 422）。
4. **chatgpt2api 原有 bug**：normalize_thinking_effort 只认 low/medium/high/xhigh→extended，
   **ultra/minimal/max/very_high 被静默置空** → API 传 reasoning_effort=ultra 时
   上游请求不带 thinking_effort，超高思考不生效（这就是「超高没生效」的一条真实路径）。
   codex-cli 0.142.5 二进制枚举已含 minimal/low/medium/xhigh/ultra。
5. 已修复：/app 与 /opt/chatgpt2api 两份 services/protocol/reasoning.py
   增加 ultra/max/very_high/super→ultra、minimal→low，重启容器后
   公有 API reasoning_effort=ultra 端到端 200（注意 max_tokens 需 ≥64，
   ultra 思考下 max_tokens=16 会返回空 content）。
6. 401 token_invalidated/token_revoked = free 号 AT 被上游吊销（id=85 复现），与模型无关。

### 使用注意
- chatgpt2api WebUI「超高」= reasoning_effort=extended（本来就透传生效）。
- API/客户端想用 codex 新档位 ultra，需 reasoning_effort=ultra（现已支持），
  max_tokens 建议 ≥64。
- 同模型+同 prompt 会命中 chat_completion_cache，对比测试请换 prompt。
