# DNS 诊断：mail.lijin.ug.cx 收不到 OpenAI OTP（2026-08-08，终版）

## 结论

`mail.lijin.ug.cx` 的权威 zone 里 **并存两条 A 记录：`127.0.0.1`（旧）与 `172.245.86.240`（新）**，
DNS 轮询返回（10 次查询 9 次 127.0.0.1、1 次 172.245.86.240；`+norecurse` 权威回答 172.245.86.240）。
OpenAI 投递验证码时大概率命中 127.0.0.1 → 邮件投递到回环，永远到不了 manymail。
**且 `172.245.86.240:25` 无 SMTP 服务（实测超时），不是收信机。**

## 证据链（全部实测）

1. **收信机实证**：`107.174.133.11:25` SMTP banner = `220 mail.lijin671.com Python SMTP 1.4.6`
   （aiosmtpd = manymail SMTP 处理器）；`172.245.86.240:25` 无任何响应。
2. **权威 zone 并存 A 记录**：`dig +noall +answer A mail.lijin.ug.cx @111.230.44.144`（ns1.9v4.com）
   多次采样见 127.0.0.1 / 172.245.86.240 交替；`+norecurse` 返回 172.245.86.240。
3. **SPF 错误**：TXT = `v=spf1 ip4:172.245.86.240 -all`，但该 IP 无 SMTP。
4. **ns2.9v4.com（138.124.102.177）曾拒绝 DNS 查询**——第二权威不可靠。
5. **单号端到端实测**（03:46-03:51，/tmp/batch_reg_test1.log）：`ed5l6oyupbfl@mail.lijin.ug.cx`
   3 次 OTP 全部超时、收件箱为空，`成功 0 / 尝试 1`。
6. **对照基线**：`mail.lijin671.com`（A=107.174.133.11）历史上成功收 88 个号。

## 修复步骤（9v4.com DNS 面板，TTL 300s ≈ 5 分钟生效）

在 `lijin.ug.cx` 的 DNS 面板：

1. **删除** `mail.lijin.ug.cx` 的 A 记录 `127.0.0.1`（旧的，必须删，否则轮询命中它）
2. **修改** `mail.lijin.ug.cx` 的 A 记录 → **`107.174.133.11`**（不要用 172.245.86.240，该 IP 无 SMTP）
3. 同样处理 `lijin.ug.cx`：删除 127.0.0.1，A → 107.174.133.11
4. **修改** TXT SPF → `v=spf1 ip4:107.174.133.11 -all`（当前 172.245.86.240 错误）

保存后验证：

```bash
bash tools/check_domain_dns.sh   # 期望 mail.lijin.ug.cx A: PASS（唯一 107.174.133.11）
```
